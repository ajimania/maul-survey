## 저장 구조 (2026-09-04 확정: Supabase)
자기소개와 출석 체크는 **Supabase RPC**로 저장한다. 커먼즈웍스의 다른 페이지들과
같은 프로젝트(`hncuvjrghniwihhfpata`)를 쓴다. Vercel 정적 배포에서 그대로 작동.

- 테이블 `mhm_members`: `name` PK · `intro` text · `att` jsonb(`{s1..s4: bool}`) · `updated_at`
- **RLS 전부 차단**, security definer RPC 두 개로만 접근:
  - `mhm_load()` — 18명 전체를 `{이름: {intro, att}}` 한 덩어리로 반환
  - `mhm_save(name, intro, att)` — 한 명 덮어쓰기. 명단에 없는 이름은 `{ok:false}`로 거부
- 클라이언트 교체 지점은 `saveMember()` / `loadAll()` 두 함수.
- `<script type="module">`이라 supabase-js를 esm으로 import한다. 인라인 onclick 없음.

⚠️ **익명 키로 테이블에 직접 insert/upsert 하지 말 것** — 401로 막힌다.
(`insert().select()`는 롤백, `upsert`는 ON CONFLICT가 기존 행을 읽어서 거부)
제주 실무자 설문(`../supabase/jeju_platform.sql`)과 같은 RPC 구조를 쓴 이유.

이전에는 `window.storage`(Claude 아티팩트 전용)를 썼으나 Vercel 배포가 불가능해 교체함.
Google Apps Script + 시트도 후보였으나, 이미 Supabase에 다른 페이지들이 올라가 있어
관리 지점을 늘리지 않는 쪽으로 정함.

## 설계상 결정 (변경 시 참고)
- 로그인 없음: 18명이 서로 아는 규모라 신뢰 기반.
  공통 암호는 **넣지 않기로 함** (2026-09-04, 장난 우려 없음).
  대신 명단에 없는 이름은 RPC가 거부해서 유령 행은 안 생긴다.
- 명단에서 성별·비고(리더 후보 등)는 의도적으로 제외 — 공개 페이지이기 때문.
- 참가 신청 버튼은 모집 종료로 삭제됨.
- 디자인: 진녹색(#1C5741 계열) + 아침 해 노랑(#F6B73C) — '헬씨모닝' 일출 콘셉트.
- 명단 확인·수정은 Supabase 대시보드에서 `mhm_members` 테이블을 직접 보면 된다.
